## 一、线程的基础知识  
##### 1. 线程与进程的区别    
- **进程（Process）**：正在运行程序的实例，进程中可以包含多个线程。是操作系统资源分配的最小单元，进程之间数据是隔离的
- **线程（Thread）**：CPU调度的最小单位，共享进程内存，容易产生数据竞态
- **协程**：用户态轻量级线程
##### 2. 并行与并发的区别    
- **并发是同一时间应对多件事情的能力**
	- 在单核CPU中，操作系统中的任务调度器会把CPU时间分给不同的程序使用
	- 一般把这种线程轮流使用CPU的做法称为并发（concurrent）
- **并行是同一时间动手做多件事情的能力**
	- 在多核CPU中，每个核都可以调度运行线程，这个时候线程可以是并行（parallel）的
##### 3. 线程创建的方式有哪些    
1. **继承Thread类**
```java
class MyThread extends Thread {
	@Override
	public void run() {
		System.out.println("线程执行");
	}
}

// 启动
new MyThread().start();
```
- 缺点：单继承限制，拓展性较差
2. **实现runnable接口**
```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("线程执行");
    }
}

// 启动
new Thread(new MyRunnable()).start();
```
3.  **实现Callable接口**
```java
class MyCallable implements Callable<Integer> {  
	@Override  
	public Integer call() {  
		return 100;  
	}  
}  
  
// 启动:FutrueTask!  
FutureTask<Integer> task = new FutureTask<>(new MyCallable());  
new Thread(task).start();  
  
// 获取结果  
Integer result = task.get();
```
4. **线程池创建线程**
```java
import java.util.concurrent.*;

// 创建线程池对象
ExecutorService pool = Executors.newFixedThreadPool(3);

pool.execute(() -> {
    System.out.println("线程执行");
});

// 关闭线程池
pool.shutdown();
```

##### 4. Runnable 和 Callable 有什么区别    
1. Runnable的 `run()` 方法没有返回值
2. Callable的 `call()` 方法有返回值，是泛型，和Future、FutureTask配合可以用来获取结果
3. Callable的 `call()` 方法允许抛出异常，而Runnable的 `run()` 方法不行
##### 5. 在启动线程的时候，run() 和 start() 有什么区别
- `start()`：用来启动线程，只能被调用一次
- `run()`：封装了要被线程执行的代码，可以被调用多次
##### 6. 线程包括哪些状态，状态之间是如何变化的
1. **状态**：
	- `NEW`：尚未启动
	- `RUNNABLE`：可运行
	- `BLOCKED`：被阻塞
	- `WAITING`：等待
	- `TIME_WAITING`：具有指定等待时间
	- `TERMINATED`：已终止
2. **状态转换**：
	- 创建线程对象是 `NEW`
	- 调用 `start()` 之后变成 `runnable`
	- 线程执行结束后变成 `terminated`
	- 在 `runnable` 过程中，如果没有获得CPU的执行权，可能会切换其它状态
		- 如果没有获取锁则进入 `blocked`
		- 如果线程调用了 `wait()` 则进入 `waiting`
		- 如果线程调用了 `sleep(50)` 则进入 `time_waiting`

使用 `join()` 方法，让线程进入waiting知道其它线程完成执行
##### 8. notify( ) 和 notifyAll( ) 有什么区别
- `notifyAll()`：唤醒所有wait的线程
- `notify()`：随机唤醒一个wait的线程
##### 9. wait() 和 sleep() 有什么区别
- **共同点**：都让当前线程放弃CPU的使用权，进入阻塞状态
- **不同点**：
	1. 方法归属不同
		- `sleep()`是Thread的静态方法
		- `wait()`和`wait(long)`都是Object的成员方法，每个对象都有
	2. 醒来时机不同
		- `sleep(long)`和`wait(long)`都会在等待相应毫秒后醒来
		- `wait()`需要用`notify()`或者`notifyAll()`唤醒
	3. 锁的性质
		- `wait`方法调用必须在synchronized代码块中获得锁，而`sleep`无限制
		- `wait`执行后会释放对象锁，允许其它线程获得该对象锁
		- `sleep`如果在synchronized代码块执行后不会释放对象锁
##### 10. 如何停止一个正在运行的线程
1. 使用退出标志flag，使线程正常退出
```java
public void run() {
	while(!flag) {
		//...
	}
}
```
2. 使用`stop()`方法（不推荐）
3. 使用`interrupt()`方法中断线程
	- 如果打断阻塞线程，则会报错InterruptedException
	- 如果打算正常线程，使用`isInterrupted()`打断状态来标记是否退出线程

## 二、线程中的并发安全  
##### 1. 线程不安全，以及其出现的原因
- 定义：多个线程同时操作同一个数据，导致最终结果与预想的不一致
- 原因：原子性，可见性，有序性
	- 原子性：操作没有一气呵成
	- 可见性：一个线程改了，另一个线程看不到
	- 有序性：代码执行顺序被编译器重排
##### 2. synchronized 关键字的底层原理
- **作用**：Synchronized【对象锁】**采用互斥的方式让同一时刻最多只有一个线程能够持有对象锁**，其它线程再想获得这个对象锁是就会被阻塞
- **底层实现**：Monitor
	- 监视器，由JVM提供，C++语言实现
	- 结构：WaitSet，EntrySet，Owner
		- Owner：关联获得锁的线程，只能关联一个线程
		- EntryList：关联没有抢到锁、目前正在blocked状态中的线程
		- WaitSet：关联处于waiting状态的线程
##### 3. synchronized同步方法和同步代码块
```java
// 1. 普通方法
// 等价于：synchronized (this) {}
// 锁是当前对象
public synchronized void method() {}

// 2. 静态方法
// 等价于：synchronized (类名.class) {}
// 锁的是class
public static synchronized void method() {}

// 3. 代码块
// 锁是指定对象
public void test() {
    synchronized (this) {
        count++;   // 只锁关键部分
    }
}
```

##### 5.  JMM（Java 内存模型）
- JMM（Jave Memory Model）定义了共享内存中多线程读写操作的行为规范，通过这些规则来规范对内存的读写操作从而保证指令的正确性（happens-before规则）
- JMM把内存分为两块，一块是私有线程的工作区域（工作内存），一块是所有线程的共享区域（主内存）
- 线程和线程之间是相互隔离的，它们之间的交互需要通过主内存
![[Pasted image 20260407002443.png|697]]
###### happens-before规则
happens-before 是 Java 内存模型中的一条规则，用于保证操作之间的可见性和有序性。如果一个操作 happens-before 另一个操作，那么前一个操作的结果对后一个操作是可见的，并且执行顺序不会被重排序。
##### 6. CAS（Compare And Swap 比较再交换）
- **定义**：一种无锁的并发控制机制，先比较主内存和工作内存中的某个变量的值是否一致，如果一致的话才对该变量进行修改和更新，否则就进入自旋。这种机制可以在无锁状态下保证线程操作数据的原子性。
- **影响**：
	- 没有锁，所以线程不会进入阻塞，效率较高
	- 但是如果竞争激烈，重试频繁发生，也会影响效率
- **底层实现**：依赖于Unsafe类来直接调用操作系统底层的CAS指令
- **乐观锁和悲观锁的区别**：
	- CAS通过自旋锁不断尝试进行变量修改，不怕别的线程来修改共享变量
	- synchronized利用对象锁防止其它线程修改共享变量
##### 7. 什么是 AQS
全称是AbstractQueuedSynchronizer，即抽象队列同步器，是一种锁机制，它是构建显示锁或者其它同步组件的==基础框架==。AQS内部维护了一个先进先出的双向队列，用于存储排队的线程。同时还有一个属性state，相当于资源，默认为0，即是无锁状态，如果有个线程把state修改为1，就说明该线程获取了资源。state的修改使用的操作是CAS。
> [!NOTE] 内置锁和显示锁
> Synchronized：内置锁，自动释放
> AQS：显示锁，手动开关

- **Q2：AQS是公平锁吗？**

	- 如果新的线程需要到队列中进行等待，只让队列中的head线程获取锁，则是公平锁
##### 8. ReentrantLock 的实现原理
- **定义**：支持重新进入的锁，调用lock方法后再次调用lock，是不会被阻塞的。相对于synchronized具备以下特点：
	- 可中断
	- 可以设置超时时间
	- 可以设置公平锁
	- 支持多个条件变量
	- 支持重入
- **实现原理**：主要利用CAS+AQS队列来实现，可支持公平锁和非公平锁，默认非公平锁。公平锁的效率往往没有非公平锁高。
##### 9. synchronized 和 Lock 有什么区别
1. **语法层面**
	- 使用synchronized是，退出同步代码锁会自动释放，但是使用lock时，需要手动调用unlock方法释放锁
2. **功能层面**
	- 均为悲观锁，都具备基本的互斥、同步、锁重入功能
	- Lock提供更多功能，例如==公平锁、可打断、可超时、多条件变量==
	- Lock有适合不同场景的实现，如ReentrantLock
3. **性能层面**
	- 没有竞争时，synchronized做了很多优化，如偏向锁、轻量级锁，性能不差
	- 但是在竞争激烈时，Lock的实现通常会提供更好的性能
##### 10. 死锁
- **死锁产生条件**：==一个线程需要同时获取多把锁==，这时就容易发生死锁。例如，线程T1持有A锁等待B锁，线程T2持有B锁等待A锁，这时就发生了死锁
- **如何判断发生了死锁**：
	- jps，jstack
	- jonsole，VisualVM：可视化工具

3. **DelayedWorkQueue**：是一个优先级队列，它可以保证每次出队的任务都是当前队列中执行时间最靠前的
4. **SynchronousQueue**：不存储元素的阻塞队列，每个插入操作都必须等待一个移除操作
##### 3. 如何确定核心线程数
1. IO密集型任务：文件读写，DB读写，网络请求。核心线程数设置为2N+1
2. CPU密集型任务：计算型代码，Bitmap转换，Gson转换。核心线程数设置为N+1
**标准回答**：
- 高并发、任务执行时间短的话，则设置为（CPU核数+1），减少线程上下文的切换
- 并发不高、任务执行时间长
	- IO密集型任务，（CPU核数 * 2+1）
	- 计算密集型任务，（CPU核数+1）
- 并发高、业务执行时间长，解决这种类型任务的关键不在于线程池而在于整体框架的设计，首先看业务里的数据是否能做缓存，其次是能否增加服务器
##### 4. 如何确定最大线程数
如果要保证CPU的利用率达到最大，那么 **最大线程数 = CPU核数 ×（1 + IO / CPU）**
- 公式推导
	1. 首先定义：
		- N = 线程数
		- C = CPU核数
		- Tc = 线程真正使用CPU的时间
		- Tw = 线程等待IO的时间
	2. CPU利用率 = Tc / (Tc + Tw)
	3. 总CPU需求 = N × Tc / (Tc + Tw)
	4. 为了把CPU吃满，N × Tc / (Tc + Tw) = C
	5. 得到公式 N = C × (1 + Tw / Tc)
###### 【阿里面试题】当你有4个CPU，IO任务和CPU任务的比例是9：1，为了把CPU吃满，最大线程数应该设置为多少？
- 因为IO任务和CPU任务的比例是9：1，所以CPU利用率是10%，为了让一个CPU的利用率最高则需要10个线程，此时我们有4个CPU，所以需要40个线程
##### 5. 为什么不能无限加线程
- 上下文切换
- 内存爆炸（OOM）
- 调度开销
##### 6. 线程池的种类有哪些
在java.util.concurrent.Executors类中提供了大量创建方法，常见的有四种：
1. **newFixedThreadPool：创建使用固定线程数的线程池**
	- 核心线程数与最大线程数一样，没有救急线程
	- 阻塞队列是LinkedBlockingQueue，最大容量为Integer.MAX_VALUE
	- 适用于任务量已知，相对耗时的任务
2. **newSingleThreadExecutor：单线程化的线程池，只会用唯一的工作线程执行任务，保证所有任务都按照指定的FIFO顺序执行**
	- 核心线程和最大线程数都是1
	- 阻塞队列是LinkedBlockingQueue，最大容量为Integer.MAX_VALUE
	- 适用于按照顺序执行的任务
3. **newCachedThreadPool：可缓存线程池**
	- 核心线程数为0，最大线程数是Integer.MAX_VALUE
	- 阻塞队列为SynchronousQueue：不存储元素的阻塞队列，每个插入操作都必须等待一个移出操作
	- 适用于任务数比较密集，但每个任务执行时间都比较短的任务
4. **ThreadPoolExecutor**：可以执行延迟任务的线程池，支持定时及周期性任务执行
##### 7. 为什么不建议使用 Executors 创建线程池
更加推荐ThreadPoolExecutor进行创建
- 对于FixedThreadPool和SingleThreadPool：允许的请求队列长度都为Integer.MAX_VALUE，可能会堆积大量的请求，造成OOM
- 对于CachedThreadPool：允许创建的最大线程数为Integer.MAX_VALUE，可能会创建大量的线程，从而导致OOM
> [!NOTE] OOM
> Out Of Memory（内存溢出）
