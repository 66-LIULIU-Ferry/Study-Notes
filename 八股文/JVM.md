
## 定义
JVM（Java Virtual Machine）是运行 Java 字节码的虚拟机，实现了 Java 的跨平台能力
- 核心作用：
	- 加载字节码（.class）
	- 执行字节码（解释/JIT）
	- 管理内存（GC）
- 好处：
	- 一次编写，到处运行
	- 自动内存管理，垃圾回收机制
##### 组成和运行流程
1. 编写 Java 代码
2. javac 编译 → 字节码（.class）
3. 类加载器加载
4. JVM执行（解释或JIT编译）

## JVM组成
##### 1. 内存结构
- 堆（Heap）：存对象
- 方法区（MetaSpace）：存类信息、常量、静态变量
- 虚拟机栈（Java Stack）：存方法调用和局部变量
- 本地方法栈（Native Stack）
- 程序计数器（PC Register）：记录当前线程执行到哪一行代码

## 垃圾回收
##### 1. Java垃圾回收机制
自动回收不再使用的对象，释放内存
- 如何判断对象是否回收：可达性分析算法
	- GC Roots从根对象出发 → 不可达 → 可回收
##### 常见GC器
1. Serial GC：单线程，会暂停所有线程
2. Parallel GC：多线程，吞吐量高
3. CMS：并发回收，停顿时间短
4. G1：分区域回收，可控停顿
5. ZGC：超低延迟
##### 2. 垃圾回收算法
1. 标记 - 清除
	- 标记垃圾 → 清除
	- 缺点：会产生内存碎片
2. 复制算法
	- 存活对象复制到新区域
	- 优点：不会产生碎片
	- 缺点：空间浪费
3. 标记 - 整理
	- 标记 → 移动对象 → 压缩
	- 常用于老年代
4. 分代收集
	- 新生代 → 复制算法，老年代 → 标记整理
##### 2. 内存碎片率高的原因
1. 使用标记-清除算法
2. 对象频繁创建和销毁
3. 大对象分配需求高
4. GC不进行整理（如CMS）
##### 如何优化内存碎片
1. 使用整理算法
2. 使用合适的GC器
3. 调整堆参数
4. 减少大对象的创建
